# Pegasus IR — PIR v0.1

Status: implemented by `compiler/pir` (checkpoint PIR0.4.1). PIR is the
authoritative intermediate representation (Phase 0 §10): it carries the
full meaning of a program, and no later stage may change that meaning. The
reference interpreter executes PIR and is the semantic oracle that native
code will be tested against.

## 1. Structure

A **module** holds monomorphic struct and enum definitions and functions.
A **function** has parameter types, a return type, stack **slots** (mutable
storage, one per source local in v0.1), typed SSA **values**, and **blocks**.
Block 0 is the entry; its parameters are the function's parameters. Every
block has parameters (SSA block arguments, no phi nodes), a list of
instructions, and one terminator.

Types: `i8 … u128`, `f16 bf16 f32 f64`, `bool`, `char`, `str`, tuples
(`()` is unit), `[T; N]`, named structs and enums (one per generic
instance), function values `fn(A) -> R` (a function plus captured values),
raw pointers, `region`, and references `&T` / `&var T`.

### 2.1 References (second-class borrows)

`&T` is a shared and `&var T` an exclusive reference to a place in a live
frame. References are second-class: only parameters, returns, SSA values and
the slots holding reference parameters may have a reference type; no
aggregate may contain one. Parameter passing follows the source mode:

| Source parameter | PIR parameter |
|---|---|
| `own T` (and extern functions, closures) | `T` (the value) |
| `in T` (default) | `&T` |
| `inout T` | `&var T` |
| result of `-> in T` | `&T` |

A function used as a value is called through a generated by-value wrapper
(`@f.value`) that borrows its own parameter slots.

**[deviation]** Phase 0 describes PIR-high as "SSA + structured control
flow". v0.1 uses an SSA control-flow graph with block arguments: simpler to
lower to and interpret, and it maps directly onto MLIR's `cf` dialect.
Structured regions (for loop-level optimization and parallel legality) are
deferred; see `DEFERRED.md` PIR-1.

## 2. Instructions

| Instruction | Meaning |
|---|---|
| `const T v` | constant (integers as two's-complement bit patterns) |
| `op.mode T a, b` | integer/float arithmetic; `op` ∈ add sub mul div rem pow shl shr and or xor; `mode` ∈ `trap` (default), `wrap` (`+% -% *%`), `sat` (`+\| -\| *\|`) |
| `neg / not / bitnot a` | negation (traps on the signed minimum), logical not, bitwise not |
| `cmp.op a, b` | comparison → `bool`; operands of one type; `eq`/`ne` on any type but functions, regions and references; `lt`/`le`/`gt`/`ge` only on integers, floats, `char` and `str` (not `bool`, spec/semantics.md §6) |
| `cast a to T` | lossless conversion (sema guarantees losslessness) |
| `load $s.path`, `store $s.path, v` | slot access; a path of `.field` and `[index]` steps; indices are bounds-checked |
| `tuple`, `struct`, `variant`, `array`, `repeat` | build aggregates |
| `extract v.i`, `index v[i]` | field of a tuple/struct; bounds-checked array element |
| `tag v`, `payload v as k.i` | enum discriminant (`u32`); payload field of variant `k` |
| `call @f(args)`, `call_indirect v(args)` | direct call; call of a function value |
| `closure @f [captures]` | function value: `f` with captured values prepended to its arguments |
| `borrow $s.path`, `borrow_mut $s.path` | a shared / exclusive reference to a place in a slot (indices bounds-checked) |
| `borrow *%r.path`, `borrow_mut *%r.path` | reborrow a place reached through a reference (exclusive only through `&var`) |
| `load *%r.path`, `store *%r.path, v` | read through a reference; write through an exclusive reference |
| `move $s.path` | PURM move: read the slot (or the field `path`) and leave it uninitialized |
| `drop $s` | end of the owner's scope: destroy the slot's remaining value, if any; a moved-from slot is a no-op (drop flag) |

Terminators: `br`, `cond_br`, `switch`, `ret`, `trap "reason"`,
`unreachable`.

**Integer semantics** (Phase 0 §7), identical in every build: `trap`-mode
`+ - * /` and `**` trap when the result does not fit; division and remainder
by zero trap; `MIN / -1` traps; `MIN % -1` is 0; shifts trap when the amount
is at least the bit width; `<<` discards shifted-out bits; `>>` is
arithmetic for signed and logical for unsigned types; `wrap` mode is
two's-complement; `sat` mode clamps.

## 3. Lowering from typed HIR

- **Monomorphization:** every non-generic function of the package is a root;
  generic functions, methods and trait default methods are instantiated on
  demand with concrete type arguments.
- **Trait calls** resolve to the implementing method for the concrete `Self`,
  or to the trait's default method.
- **Locals** live in slots; parameters are stored to their slots on entry.
- **Patterns** compile to test-and-branch code (tags, comparisons, ranges,
  element and field projections); or-patterns try alternatives in order.
- **Loops:** `loop` passes break values as block arguments; `for` over an
  inclusive range stops at the bound without computing `bound + 1`.
- **`defer`** runs, in reverse order, at every exit from its scope: normal
  end, `return`, `break`, `continue`.
- **`?`** returns `None` or `Err(e)` in the function's return type.
- **Contracts:** `requires` is checked on entry and `ensures` before every
  return (with `result` bound): Phase 0 keeps unproven contracts as runtime
  checks [R]; the prover (Phase 7) may later remove proven ones.
- **Closures** are lifted to functions whose leading parameters are the
  captured values (captured by value in v0.1).
- **Constants** become parameterless functions called at each use.
- **Ownership** (spec/purm.md): consuming uses of non-Copy locals (marked
  `MoveLocal`/`MovePath` by the PURM checker) lower to `move`. Every scope —
  block, match arm, `if let` branch, loop iteration, and the function root
  for `own` parameters — owns the non-Copy locals it binds; at each exit,
  after the scope's `defer`s, they are dropped in reverse declaration order.
  Assigning a whole local drops its old value first. Non-Copy captures move
  into closures.

Lowering errors (`L` codes):

| Code | Meaning |
|---|---|
| L001 | internal lowering limitation (unsupported place, constant without value) |
| L002 | assignment to a captured variable inside a closure (capture modes belong to PURM) |
| L003 | an expression that cannot be returned as a borrow reached lowering (PURM's O005 prevents it) |

## 4. Verifier

Run after lowering (and, in later phases, after every pass); a failure is a
compiler bug. It never panics on malformed input: every identifier is
range-checked before use. It checks:

- types are well formed (struct/enum identifiers exist) for every value,
  slot, parameter, return type and definition field;
- every declared value is defined exactly once (block parameter or
  instruction result), whether used or not;
- every use is dominated by its definition (dominator tree,
  Cooper–Harvey–Kennedy);
- references are top-level only (never inside tuples, arrays, structs,
  enums or function types); `store` and exclusive reborrows need `&var`;
  extern functions take and return no references;
- **reference slots** hold reference parameters and nothing else: a slot of
  reference type is written exactly once, as a whole, in the entry block,
  with an entry-block parameter of its type, and is not read in the entry
  block before that write; it cannot be borrowed (reborrow through the
  reference), moved or dropped;
- **provenance:** a returned reference must be *proven* to point only into
  storage reached through the function's reference parameters: its origin
  must include a parameter and must not include the function's own slots.
  Origins flow through reborrows, slot stores, loads and moves, block
  arguments, and calls (a returned reference is tied to every argument). A
  reference whose origin no rule establishes is rejected: the analysis fails
  closed. The lattice is finite and updates only add facts, so iteration
  reaches the least fixed point within `2 × (values + slots) + 1` rounds;
  exceeding the bound is reported as an error, never accepted;
- every instruction kind is type-checked: constants (and integer bit
  patterns within their width), unary and binary operations with their
  legal operand types and overflow modes (`wrap`/`sat` only for integer
  `add`/`sub`/`mul`; floats and `bool` have no mode; shift amounts and integer
  exponents are unsigned), comparisons, casts (lossless only), slot access
  and paths, aggregates (arity, element and field types), extraction and
  indexing (`usize` index), tags and payloads, direct and indirect calls,
  closures (captures match the callee's leading parameters), `move`, `drop`;
- block arguments against block parameters; branch targets exist;
  `cond_br` takes a `bool`; `switch` takes an integer with distinct cases
  that fit its type; returned values have the function's return type; entry
  parameters equal the function parameters.

`compiler/pir/tests/verify_mutation.rs` compiles every corpus program and
checks that thousands of single invalid mutations are all rejected.

## 5. Reference interpreter

Executes PIR on an explicit frame stack. It refuses instructions the
verifier would reject (e.g. an illegal overflow mode) instead of computing
them. Reading a moved-from slot traps as a PURM violation — a second line of
defence; the checker makes it unreachable for accepted programs. A
reference is a frame-stamped pointer (frame, slot, path); dereferencing one
whose frame has returned traps as a dangling reference. `drop`
events are recorded (`Interp::drops`) for the destruction tests. Deep
recursion cannot overflow the host stack: the call depth limit (100 000
frames) is a `stack overflow` trap, and native code enforces the same limit
(spec/native.md). A step limit guards tests against runaway loops; it is an
interpreter guard, not language semantics. Every
materialized check traps with a reason and a backtrace. Not implemented in
v0.1 (they trap with an explicit message, never compute a wrong result):
`f16`/`bf16` arithmetic and calls to `extern` functions.

`pegasus run file.peg` runs `fn main()` and prints its result (if not
`()`); a trap exits with status 101.

## 6. Serialization

Verified modules cross the Rust/C++ boundary as PIRB files
(spec/pir-bridge.md); `pegasus pirb file.peg out.pirb` writes one.

## 7. Not yet in PIR v0.1

Explicit `end_borrow` markers and borrow contracts inferred per parameter
(v0.1 ties a borrowed result to every borrowed input); drops of temporaries and of overwritten fields; effects and precision policies as
attributes; async state machines; layout and placement annotations; a
textual parser and binary format (round-trip); structured regions. See
`DEFERRED.md`.
